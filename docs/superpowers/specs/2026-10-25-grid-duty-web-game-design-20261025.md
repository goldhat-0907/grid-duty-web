## 1. 背景与目标

将《电网值班室》关卡数据包实现为**体验式、场景式教学游戏**，面向电气工程与能源动力工程专业大学生、电网新入职员工。玩家扮演值班员，在"会出事故"的高逼真值班室环境中，通过实际操作电网（调压、潮流转移、继保定值、新能源消纳、储能充放、算力调度、台风应急）掌握电力系统相关课程知识与技能。游戏内通过任务简报、实时状态反馈、结算复盘卡（`review_template`）三层次给出教学提示。

### 成功标准

- 竖屏网页游戏，浏览器直接访问，无需服务器。
- 数据包 4 章 7 关全部可玩，关卡数值全部从 JSON 读取，不写死。
- 每关存在至少一组可行解，且可在 `steps_limit` 内完成（数据包 `validator` 规则）。
- 界面达到"深色 SCADA 值班室"高逼真度，纯矢量绘制（符合数据包 `engineering-flat` / `assets: none` 规范）。
- 教学性：每关结束后按 `review_template` 生成复盘卡，解释正确/错误操作的原理并给出记忆口诀。

## 4. 玩法循环

数据包定义循环：`brief → operate → settle → review`。

1. **brief**：展示关卡标题、任务简报（`level.brief`）、目标提示、倒计时、可用技能。
2. **operate**：中部 SVG 拓扑画布 + 底部控件台。顶部 HUD 常驻：剩余时间、已用步数、四维实时得分。每次操作：
   - 将操作应用到引擎 → 重新计算全网状态 → 拓扑/仪表/告警即时刷新。
   - 计 1 步（技能使用计入 `economy` 步数）。
   - 非法操作即时拒绝并给出短提示（触控设备配短震动）。
3. **settle**：时间到或玩家提交时结算：
   - 按 `level.goals` 逐项判定达标（电压带、过载、弃电率、SOC 带、需量、动作链等）。
   - 按 `scoring` 计算四维得分（安全/经济/绿色/效率加权）→ 星级（一星通关/二星四维全达标/三星=二星+复盘答题正确+步数在优秀线内）。
   - 发放金币（20/35/50）与奖励（`rewards.cards`/`skills`/`title_xp`）。
4. **review**：按 `level.review_template` 生成复盘卡：`did`（插值玩家真实操作，如"你把分接头动了 3 档"）、`why`（原理讲解）、`remember`（记忆口诀）；三星评审要求回答一道知识点题目。
5. 通关后进入章节地图，解锁下一关；`crew` 角色随第二章解锁，`trader`/`blue_team` 随第三章解锁（本章全部实现关卡中使用到的角色面板均需可用）。

### HUD 计时器

- 每关 `time_limit` 秒（75~180），倒计时至 0 强制结算。
- 效率分 = f(用时比例, 步数与 `steps_excellent`/`steps_limit` 的关系)。

## 5. 引擎模块规格

### 5.1 潮流计算 `powerflow.js`

支撑 GS-1-1、GS-1-2。实现小型牛顿-拉夫逊潮流（4~5 母线，极坐标，简化雅可比），输入 `grid.nodes`（含负荷/发电/电压）、`grid.branches`（z_pu 阻抗标幺、`rating_mva`、`out_of_service` 检修标志）、`controls` 当前状态（分接头、并联电容器、机组出力、甩负荷）。输出：

- 各母线电压标幺（用于 0.95~1.05 电压带判定）。
- 各支路潮流（MVA）与负载率 = 潮流/额定（用于过载与热稳判定，负载率 >100% 判过载，颜色随负载率渐变）。
- 网损百分比（GS-1-1 `loss_max_pct: 5.5` 判定）。

**GS-1-1 单辐射网首日值班**（35kV，母线 B1~B5，分接头 T1_tap 档位范围 [-4,4]、step 0.625kV，电容器 C3_bank 0~4 组 × 5Mvar）：
- 目标：电压合格率 100%、电压带 [0.95,1.05]、线损 ≤5.5%、步数 ≤8（优秀 5）。
- 教学点：`k-var-voltage` 先补无功再动分接头；`k-tap-side-effect` 分接头整体抬高二次侧电压但相邻节点仍会越下限。

**GS-1-2 检修日的潮流转移**（220kV 环网 A-B-C-D，LBC 检修停电，LAC 逼近热稳 120MVA）：
- 控件：机组 G_A 出力 [80,240]MW、主变 T_B_tap 分接头、C 点甩负荷 [0,30]MW（甩负荷扣安全分）。
- 目标：无过载、电压带 [0.95,1.05]、甩负荷 =0、步数 ≤9（优秀 6）。
- 教学点：`k-n1` N-1 校验、`k-load-transfer` 潮流转移集中到电气距离最短路径、`k-thermal-limit` 热稳极限。

### 5.2 继保逻辑 `relay.js`

支撑 GS-1-3。10kV 馈线三段式过流保护，3 套继电器 R1（变电站）/R2（中段）/R3（末端），各设启动电流（pickup，A）与时间定值（t，ms）。逻辑：

- 计算故障点（`fault_km: 8.0`，三相短路）短路电流沿馈线分布。
- 对每套继电器判定：故障电流 > 启动值则启动，按时间定值计时，最小时间者跳闸。
- 判定项：只跳 R2（`trip_only: ["R2"]`）、级差 ≥300ms（`grading_ms_min`）、不越级（`no_overreach`，上级不能比下级快）、灵敏性（`sensitivity`，故障电流 ≥ 启动值的一定倍数）。
- 每套继电器 pickup 可调范围 [200,900]/[150,700]/[80,500] A，时间 [0,900] ms。
- 教学点：`k-selectivity` 选择性、`k-grading` 级差（越靠近电源时间越长）、`k-overreach` 越级跳闸扩大停电。

### 5.3 新能源消纳 `renew.js`

支撑 GS-2-1。凌晨 3 点：风电 280MW（可调 120~320）、负荷 120MW、外送通道上限 150MW、储能 50MW/100MWh SOC 0.35。

- 控件：弃风 curtail [0,160]MW、储能充电 charge [0,50]MW、外送 export [0,150]MW。
- 功率平衡：风电 + 储能放电 + 外送 = 负荷 + 储能充电 + 弃风 + 平衡项；弃电率 = 弃风/风电。
- 目标：弃电率 ≤10%、SOC 带 [0.1,0.9]、外送不超限、步数 ≤6（优秀 4）。
- 教学点：`k-curtail` 弃电本质是当下无可调空间、`k-absorption` 先存再送最后弃、`k-peak-valley` 峰谷。

### 5.4 储能套利 `storage.js`

支撑 GS-2-2。储能 50MW/100MWh，SOC 0.2，效率 0.92，循环成本 45 元/MWh，24 小时电价曲线（280→980 元/MWh，双峰双谷）。

- 控件：4 个时段槽（0-5/10-15/17-19/21-24 时）各选 充电/放电/停机 + 功率 [0,50]MW。
- SOC 演化：充放按效率 0.92；限制 SOC ∈ [0.1,0.9]。
- 套利利润 = 放电收入 − 充电成本 − 循环损耗成本；目标净利 ≥0、SOC 带、功率 ≤50、循环次数 ≤2、步数 ≤8（优秀 5）。
- 教学点：`k-soc` SOC 双界是寿命与安全约束、`k-cycle-life` 深放深充衰减循环寿命、`k-arbitrage` 先算循环成本再算价差。

### 5.5 算力调度 `compute.js`

支撑 GS-3-1。西部园区（风电富余、绿电 0.86、电价 0.31、弃电风险）、东部园区（绿电 0.22、电价 0.78、晚高峰超需量 180MW 上限）、联络线 120MW，窗口 18:00-22:00。

- 6 个任务：T1 预训练（可迁移）、T2 微调（可迁移）、T3/T4 在线推理（不可迁移、硬时延）、T5 离线渲染（可延迟 12h）、T6 数据清洗（可延迟 4h）。
- 控件：任务迁移（目标 东/西/延迟）、储能削峰 [0,40]MW、需量申报 [150,220]MW。
- 目标：绿电比例 ≥0.85、东部需量不超申报、任务准时率 100%、推理不断（`inference_kept`）、步数 ≤10（优秀 6）。
- 教学点：`k-compute-power-coordination` 算电协同、`k-flexible-load` 可迁移的是可延迟的（训练/批处理），不可迁移的是实时的（推理）、`k-demand-management` 需量管理、`k-green-power-trace` 绿电溯源。

### 5.6 台风夜 `typhoon.js`

支撑 GS-4-1（Boss，180 秒，多角色协作）。

- 三条告警：L17 线路跳闸重合失败（high）、光伏 40→3MW（high）、数据中心 UPS 剩 6 分钟（critical）。
- 动作链序贯：`isolate_fault → restore_critical_load → shift_compute → restore_normal`；乱序扣 25 分、漏步扣 40 分。
- 控件：L17 隔离开关、发电车保电（数据中心）、任务迁移（东/西）、储能放电 [0,60]MW。
- 目标：动作链正确、关键负荷不丢、电压带 [0.95,1.05]、180 秒内、步数 ≤14（优秀 9）。
- 教学点：`k-emergency-order` 先隔离再保关键后恢复、`k-fault-isolation` 故障未隔离就恢复会二次送电、`k-load-priority` 负荷分级。

## 6. 评分、星级、技能、角色系统

### 6.1 四维评分 `scoring.js`

按 JSON `scoring.dimensions`：安全 0.35 / 经济 0.25 / 绿色 0.20 / 效率 0.20。每维由该关操作结果计算（如安全分由违规动作/越级跳闸/甩负荷扣减，经济分由线损/弃电/寿命损耗/偏差考核，绿色分由消纳率/碳排，效率分由用时与步数）。各维加权求和得总分。

星级规则（`scoring.stars`）：
- 一星：通关（goals 达标）。
- 二星：四维全部达标。**达标线定义**（该关未触发对应维度的扣分项）：安全维 = 无违规动作/越级跳闸/超限甩负荷；经济维 = 线损/弃电/寿命损耗/偏差考核均在 goals 限内；绿色维 = 新能源消纳率达标；效率维 = 步数 ≤ `steps_limit`。各关在实现计划中按具体 goals 细化。
- 三星：二星 + 复盘答题正确 + 步数 ≤ `steps_excellent`。

金币：一星 20 / 二星 35 / 三星 50（`scoring.coins`）。首次通关额外发放 `rewards.coins`（30~80）。

### 6.2 技能系统 `skills.js`

从 JSON `skills` 读取 13 项技能，字段：`name`、`source`（解锁条件）、`effect`、`limit`（次数/冷却）、`cost`（步数代价）、`knowledge`。已实现 7 关所需的 MVP 技能（数据包 `mvp: true`）：

- **万用表精通**（multimeter）：读取任意节点电压电流，每关 3 次，代价 1 步。课程：电路测量。
- **红外测温**（thermal_cam）：高亮即将过热的接头线夹，冷却 30s，代价 1 步。课程：接触电阻与发热。
- **验电接地**（ground_check）：一键规范验电接地，免一次误送电事故，每关 1 次，0 代价。课程：两票三制。
- 其余技能（钳形表、绝缘摇表、电缆测距、相序判别、发电车、移动储能、无人机、工作票、带电作业、黑启动）在对应关卡中按 JSON 挂接；解锁条件按 `source` 实现。

规则（`skill_rules`）：技能只扩展信息/省时间/加容错，不直接给出正确操作；每次使用计入步数影响 economy；`skill_locked` 关禁用全部技能；基础技能跨角色继承。

### 6.3 角色系统

8 种角色（调度员/继保/新能源场站/储能站长/算力能源经理/配网抢修班/市场交易员/蓝队安全工程师）。本轮 7 关使用：dispatcher（GS-1-1/1-2）、protection（GS-1-3）、re_operator（GS-2-1）、storage_chief（GS-2-2）、compute_manager（GS-3-1）、multi（GS-4-1）。各角色有专属面板类型与关注维度（`role.panel`/`focus`）。

### 7.3 拓扑渲染 `topology.js`

- 按 `grid.nodes` 布局母线（电源用发电机图标、变电站用建筑图标），按 `grid.branches` 连线。
- **潮流动画**：SVG `stroke-dasharray` + CSS 动画，电流方向 = 潮流方向；线宽与颜色随负载率变化（<70% 绿、70~100% 琥珀、>100% 红闪）。
- 节点电压显示小表计，越界时节点呼吸红色告警。
- `out_of_service` 支路显示为断开/检修标记。
- 设备 mimic 图例：断路器（方框+斜线）、隔离开关、主变（圆圈绕组符号）、电容器组、储能方舱（电池符号）、分接头（箭头上下）、UPS/数据中心（服务器图标）。
- 告警横幅：顶部滚动滚入 + 闪烁，按 severity 着色（high 琥珀 / critical 红）。

### 7.4 仪表与图表 `charts.js`

- 数字表计：电压（kV）、电流（A/MVA）、频率（Hz，静态装饰）、功率。
- 指针式电压表（SVG 圆弧刻度 + 指针动画）用于 GS-1-1/1-2 主要母线。
- 价格曲线（GS-2-2）：24 小时电价折线 + 充放计划分时着色。
- 出力曲线（GS-2-1）：风电/负荷/外送/储能的堆叠面积图。
- SOC 电量条（GS-2-1/2-2）：0.1~0.9 区间标记，当前 SOC 显示。

### 7.5 控件 `controls.js`

按 JSON `controls` 渲染对应控件类型：
- tap：档位拨盘（-4~4，步进提示分接头变比变化）。
- shunt：电容器组投切开关（0~4 组）。
- gen_dispatch：出力滑杆。
- relay_pickup / relay_time：定值数字滑杆 + 当前定值表。
- curtail / export / storage_charge / storage_discharge / demand_declare：滑杆。
- schedule_slot：时段卡（充电/放电/停机三选 + 功率滑杆）。
- task_migrate：任务列表拖选目标园区/延迟。
- switch：开关按钮（合/分）。
- shed：甩负荷滑杆（红色危险样式）。

操作反馈：有效操作即时刷新全网状态；无效操作控件抖动 + 短提示；所有操作计入步数。

### 7.6 结算卡与复盘卡 `settle.js` / `review.js`

- 结算卡：四维得分条（横向条形 + 加权总分）、星级动画（1~3 星逐颗点亮）、金币滚动。
- 复盘卡：`review_template` 插值渲染（`did` 填入真实操作值，`why`/`remember` 展示）；三星评审含一道知识点选择题，答对才给三星。

## 8. 进度与持久化 `state.js`

`localStorage`（键 `grid-duty-web.progress.v1`）保存：
- 章节解锁状态（ch1 默认；`crew` 角色及 ch2 由 GS-1-3 通关解锁；ch3 由 ch2 通关解锁）。
- 每关：最高星级、累计金币、是否通关、最佳步数。
- 已收集技能卡（`rewards.cards`）、已解锁技能、职称经验 `title_xp`。
- 全局图鉴（`codex.js`）：解锁过的技能/知识点按 `knowledge` id 汇总展示。

提供"重置进度"按钮（清 localStorage）。
